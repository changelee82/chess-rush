Web端 - ChessRush - 棋盘页面布局规范
==========================================


一、定义页面区域

| 区域 | 说明 |
|------|------|
| 导航栏 | 屏幕最上方，显示标题，覆盖顶部安全区 |
| 安全区 | 通过 viewport-fit=cover + env(safe-area-inset-*) 处理。导航栏可覆盖顶部安全区，页面区需避开左右安全区，底部安全区预留 padding-bottom。无安全区的设备 inset 值为 0 |
| 页面区 | 导航栏下方至底部安全区上方，显示页面内容 |
| 棋盘区 | 显示棋盘，由 JS 计算精确正方形尺寸，不被 CSS 压缩或拉伸 |
| 上位区 | 放置自定义视图，flex 填充棋盘区外的剩余空间 |
| 下位区 | 放置自定义视图，flex 填充棋盘区外的剩余空间 |



二、布局模型

布局方法：JS 计算棋盘精确尺寸，其余区域用 Flex 填充剩余空间。
原因：棋盘必须保持精确正方形且格子为整数像素以避免模糊，CSS Grid 的自动分配无法保证这一点。

| 层级 | 布局方式 |
|------|----------|
| 页面区 | Flex（竖屏纵向，横屏横向） |
| 棋盘区 | JS 计算的固定宽高，inline style 注入，好处是优先级最高，CSS 的任何规则都无法覆盖或压缩它，棋盘尺寸就"钉死"了 |
| 上位区 | flex: 1 填充剩余空间 |
| 下位区 | flex: 1 填充剩余空间 |


三、确定横竖屏

| 步骤 | 公式 / 方法 |
|------|-------------|
| 页面区宽度 | 视口宽度 − env(safe-area-inset-left) − env(safe-area-inset-right) |
| 页面区高度 | 视口高度 − 导航栏高度 − env(safe-area-inset-bottom) |
| 横竖屏判定 | window.matchMedia('(orientation: portrait)')，matches=true 为竖屏 |
| 切换监听 | resize 事件，触发重新计算 |


四、竖屏布局

页面区内部纵向 Flex 排列。

棋盘边长计算：
  棋盘边长 = min(页面区宽度, 页面区高度 − 48 − 48)
  棋盘边长 = Math.max(棋盘边长, 160)   // 最小保底

DOM 结构与属性：

  page（水平垂直拉伸，纵向排列）
  |
  +-- 导航栏
  |     固定高度，不拉伸不压缩
  |
  +-- 页面区
  |     水平拉伸，纵向 Flex
  |     顶 -> 导航栏底边
  |     底 -> 底部安全区顶边
  |     |
  |     +-- 上位区
  |     |     flex: 1，水平拉伸
  |     |     最小高度 48px
  |     |
  |     +-- 棋盘区
  |     |     JS 固定宽高（inline style）
  |     |     水平垂直居中，不被压缩
  |     |
  |     +-- 下位区
  |           flex: 1，水平拉伸
  |           最小高度 48px
  |
  +-- 底部安全区
        padding-bottom: env(safe-area-inset-bottom)

Flex 约束说明：
- 上位区和下位区各 flex: 1，平分棋盘区以外的剩余空间
- 棋盘区垂直居中由上位区和下位区各 flex:1 平分剩余空间实现
- 上位区/下位区内部可添加用户自定义视图，布局方式用户自定义
- 棋盘区不参与 flex 伸缩，固定尺寸居中
- 若剩余空间不足，棋盘边长自动缩小（计算公式已减去最小高度）


五、横屏布局

页面区内部横向 Flex 排列。

棋盘边长计算：
  棋盘边长 = 页面区高度
  棋盘边长 = Math.max(棋盘边长, 160)   // 最小保底

DOM 结构与属性：

  page（水平垂直拉伸，纵向排列）
  |
  +-- 导航栏
  |     固定高度，不拉伸不压缩
  |
  +-- 页面区
  |     横向 Flex
  |     左 -> 左侧安全区右边
  |     右 -> 右侧安全区左边
  |     顶 -> 导航栏底边
  |     底 -> 底部安全区顶边
  |     |
  |     +-- 棋盘区
  |     |     JS 固定宽高（inline style）
  |     |     垂直居中，左对齐
  |     |
  |     +-- 上位区
  |     |     flex: 1，顶对齐
  |     |     高度 = 页面区高度 x 50%
  |     |     左 -> 棋盘区右边
  |     |     右 -> 页面区右边
  |     |
  |     +-- 下位区
  |           flex: 1，底对齐
  |           高度 = 页面区高度 x 50%
  |           左 -> 棋盘区右边
  |           右 -> 页面区右边
  |
  +-- 左侧安全区
  |     padding-left: env(safe-area-inset-left)
  |
  +-- 右侧安全区
  |     padding-right: env(safe-area-inset-right)
  |
  +-- 底部安全区
        padding-bottom: env(safe-area-inset-bottom)

Flex 约束说明：
- 棋盘区不参与 flex 伸缩，固定尺寸左对齐垂直居中
- 上位区和下位区在棋盘右侧水平拉伸，高度各为页面区高度的 50%
- 上位区 justify-content: flex-start，下位区 justify-content: flex-end
- 上位区/下位区内部可添加用户自定义视图，布局方式用户自定义


六、导航栏说明

| 属性 | 值 / 说明 |
|------|-----------|
| 高度 | 默认固定 |
| 高度注入 | 通过 CSS 变量 --nav-bar-height 注入根元素 |
| 定位 | position: fixed; top: 0; left: 0; right: 0;，覆盖顶部安全区 |
| 页面区避让 | padding-top: var(--nav-bar-height) |
| 内部布局 | 标题（居中）+ 返回按钮（右）|
| 非微信回退 | iOS 44px / Android 48px，通过 window.__wxConfig 或 UA 判断 |


七、棋盘区

| 属性 | 值 / 说明 |
|------|-----------|
| 尺寸 | JS 计算的固定宽高，inline style 注入，不被 CSS 压缩 |
| 边框 | 1px 蓝色边框 |
| 内间距 | 3px padding |
| 结构 | 顶部列标（a-h）→ 棋盘主体（左侧行标 1-8 + 8×8 格子）→ 底部列标 |
| 棋盘内边长 | 棋盘边长 − 2px（边框）− 6px（间距 3px × 2） |
| 格子大小 | Math.floor(棋盘内边长 ÷ 8)，取整数避免亚像素模糊 |
| 格子实际占用 | 格子大小 × 8，多余像素通过居中消化 |
| 行标/列标尺寸 | 宽度/高度 = 格子大小，与格子对齐 |


八、上位区

| 属性 | 值 / 说明 |
|------|-----------|
| 容器 | 用户在上位区添加视图时再定义布局方式 |
| 溢出处理 | 不压缩，用户自定义 |


九、下位区

| 属性 | 值 / 说明 |
|------|-----------|
| 容器 | 用户在下位区添加视图时再定义布局方式 |
| 溢出处理 | 不压缩，用户自定义 |


十、横竖屏适配

| 步骤 | 说明 |
|------|------|
| 监听 | resize 事件（覆盖 orientationchange） |
| 重算流程 | 判定横竖屏 → 计算棋盘边长 → 更新棋盘区 inline style → Flex 自动重排 |
| 过渡动画 | 无（棋盘尺寸变化不适合 transition，会导致模糊） |
| 导航栏 | 切换后高度不变，无需重算 |


十一、边界与降级规则

| 场景 | 规则 |
|------|------|
| 棋盘最小边长 | 160px，低于此仍渲染但体验下降 |
| 上位区/下位区最小高度 | 48px，低于此文字可能溢出 |
| 极端窄屏（< 320px） | 上位区/下位区内用户自定义视图 |
| 极端宽屏（> 2560px） | 棋盘边长上限 = 页面区高度（横屏）或页面区宽度（竖屏），不无限放大 |
| 非微信环境 | 导航栏高度回退为 iOS 44px / Android 48px |
